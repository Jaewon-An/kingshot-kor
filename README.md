# 킹샷 배치 시뮬레이터

[wablelife 킹샷 배치 시뮬레이터](https://www.wablelife.com/2026/05/kingshot-map.html)와 같은 조작·좌표계·거리 계산을 가진 배치 툴입니다.
**실제 지도 데이터**(산/호수 장애물, 연맹 자원지 6,499곳, 요새·성소·전초기지와 건설 금지구역) 위에
관리자가 저장·게시한 **KOR(#2382) 배치도**만 보여 줍니다. 외부 실시간 데이터는 쓰지 않습니다.

## 실행

node server.js        # http://localhost:8080  (Node 18+, 의존성 없음)

### 배치도 게시하기
1. `/v1/admin`에서 로그인하고 편집합니다. 편집 중인 내용은 관리자 브라우저에만 임시 저장됩니다.
2. 지도 데이터 ▸ **게시하기 (모두에게 반영)** 를 누르면 바로 모든 사람의 `/v1` 화면에 반영됩니다.
   Cloudflare에서는 KV에, 로컬 서버에서는 `layouts/current.json` 파일에 저장됩니다.
   Cloudflare KV 특성상 다른 지역까지 퍼지는 데 최대 1분쯤 걸릴 수 있습니다.

"게시본과 비교"는 편집 중인 배치와 게시본의 차이(이동·추가·삭제)를 보여 줍니다. 항목을 누르면 그 기물만 게시본대로 되돌립니다.
게시할 때마다 직전 게시본이 KV의 `previous` 키(로컬은 `layouts/current.previous.json`)에 한 단계 보관됩니다.

### 신규 자리 배치 (v2)
곰덫을 옥토 안(곰덫2 523,720 / 곰덫1 511,720 — 곰덫1이 곰덫2 왼쪽, 평원 본부 523,759)으로 옮긴 배치입니다. USB "킹샷2382_곰덫배치"의 작업(작전도·자리 안내·이름 배치 X−2-L 안)을 옮겨 왔습니다.
- 게시본은 `/v1`과 따로 있습니다: Cloudflare KV `v2` 키(직전본 `v2_previous`), 로컬은 `layouts/v2.json`. 첫 게시 전에는 `layouts/v2.json`을 보여 줍니다. API는 `GET/PUT /api/v2/layout`(기존 배치도는 `/api/layout` 그대로).
- `/v2/admin`에서 편집하고 **게시하기**를 누르면 `/v2`에 반영됩니다. `/v1`의 배치는 바뀌지 않습니다.
- **이름 배치 다시 계산**: 기존 배치도(`/v1` 게시본)에서 각자 더 가까운 곰덫 기준 상대 자리를 새 곰덫 자리로 옮기고, 막힌 사람만 가까운 빈칸으로 옮깁니다. 그다음 두 곰덫 모두 2줄까지 비는 도시 칸이 없도록 가장 바깥 연맹원을 당겨 채우고(곰덫 2줄 확보), 깃발과 빈자리(합계 100자리)를 다시 계산합니다. 깃발이 꼭 서야 하는 칸이나 산·자원지 칸은 비어 있을 수 있습니다. 같은 계산을 명령으로도 할 수 있습니다:
  ```
  node tools/make-v2-layout.mjs                              # layouts/current.json → layouts/v2.json
  node tools/make-v2-layout.mjs --t2 523,720 --t1 535,720 --from layouts/current.json --out layouts/v2.json   # 곰덫1 오른쪽 (X−2 안)
  node tools/make-v2-layout.mjs --check layouts/v2.json      # 규칙 검사 (겹침·장애물·영토·깃발 연결·오와 열)
  node tools/make-v2-layout.mjs --secure 0                   # 곰덫 2줄 확보 없이 (USB 원본 계산과 같음)
  # (선택, 기본 꺼짐) 곰덫별 확보 줄 수와 기존 줄 우선 배치: --secure2 3 --secure1 2 --vip2 2 --vip1 1
  #   깃발도 같은 구역을 비워 두려면: node tools/plan-flags.mjs --write --secure2 3 --secure1 2
  ```
- 엔진은 [v2/core.js](v2/core.js)(USB `core.js`), 이름 배치·검사는 [v2/plan.js](v2/plan.js)(USB `assign2.js`·`verify-json.js`)입니다. 지형 데이터는 `mapdata.js`와 같아서 `--secure 0`이면 USB 결과물을 그대로 재현합니다(2026-09-29 명단 기준: 곰덫1 왼쪽 `layouts/kor_2382_2026-10-15_X2-L_usb.json`, 오른쪽 `layouts/kor_2382_2026-10-15_X2_usb.json`). 최신 명단으로 계산한 오른쪽 안은 `layouts/kor_2382_2026-10-15_v2_X2_right.json`에 있습니다(`/v1/flags?layout=파일이름`으로 보기).
- 닉네임이 `빈자리`로 시작하거나 `Player`인 성은 빈자리로 봅니다. `개척자`는 이용자가 아니라서 연맹원으로 세지 않고 v2 배치에도 넣지 않습니다(`v2/plan.js`의 `NON_MEMBERS`). 새 연맹원이 오면 `/v2/admin`에서 빈자리 이름만 바꾸면 됩니다.
- 다른 연맹 영토는 X 544 이상, Y 724~764로 가정합니다(`v2/plan.js`의 `BLOCKS_DEFAULT`).
- **현재 설치된 깃발**: `/v1/flags`와 같은 [layouts/flags.json](layouts/flags.json)의 깃발입니다. `/v2` 지도는 본부·이 깃발(채운 깃발 칸)·신규 배치 깃발(아직 없는 것은 빈 칸에 설치 순서 번호)의 영지 범위를 모두 같은 파란 연맹 영토로 그립니다(`/v2/map`은 지금 깃발을 불러오지 않아 신규 배치 깃발 기준 영토). `/v2/admin`(신규 자리 도구)은 청록 점선 영토로 함께 보여 줍니다. 2026-10-15 스크린샷(`screenshot/v2`)에는 좌표가 없어서, 왕관 연맹 자원지와 본부 위치로 화면을 맞춰 깃발 20개(본부→옥토)의 좌표를 계산했습니다. 영토 경계선과 칸 단위로 일치하며, 이 깃발들은 영토 꼭짓점끼리만 닿아도 이어져 있습니다.
- **깃발 재배치 최적화·작업 순서** ([v2/flagplan.js](v2/flagplan.js)): 지금 깃발을 최대한 재사용하면서 곰덫·성·빈자리·연맹 자원을 모두 덮고 본부와 이어지는 깃발을 찾습니다(새로 지을 깃발 최소). 성 자리는 그대로이고 빈자리만 영토 안에서 다시 놓습니다. 연결 규칙은 자동입니다: 변 접촉으로 같은 결과가 나오면 그것(어느 규칙에서도 통함), 꼭짓점 접촉이 더 적게 지을 때만 꼭짓점. 깃발 번호는 작업 순서입니다: 새로 지을 깃발이 설치 순서대로 1, 2, …번이고, 이미 서 있어 그대로 쓰는 깃발이 그 뒤 번호입니다. 번호 순서대로 설치하면 매번 본부와 이어지고, 곰덫·가까운 줄을 먼저 덮습니다. 철거는 꼭 필요한 것만 표시합니다(새 배치의 성·곰덫·자원 자리 위에 선 깃발). 쓰지 않는 다른 깃발은 그대로 둬도 됩니다. 깃발 수 상한(기본 없음)을 주면 설치 전에 비울 깃발도 순서에 넣습니다.
  - `/v2/admin` 신규 자리 도구 ▸ **최적화해서 불러오기**(편집 중 배치의 깃발·빈자리를 바꿈, 게시해야 반영) / **작업 순서만 보기**. `/v2`는 게시된 배치 기준 작업 순서를 보여 주고 꼭 철거할 깃발을 빨간 X로 표시합니다.
  - 명령: `node tools/plan-flags.mjs [--write] [--rule auto|corner|edge] [--cap 개수] [--keep-spares]`, 번호만 다시 매기기 `--renumber --write`. `make-v2-layout.mjs`로 배치를 다시 만들면 깃발이 엔진 계산으로 돌아가니, 그 뒤에 `plan-flags.mjs --write`를 다시 실행하세요.
  - 규칙 검사(`/v2/admin`·`make-v2-layout.mjs --check`)의 깃발 연결 기본값도 게임에서 확인한 꼭짓점 접촉입니다(변 접촉 배치는 그대로 통과).

- [layouts/sgd.json](layouts/sgd.json): 배치(사이트 기물 형식). 곰덫 `사냥 함정 1`, 깃발 `깃발 N`(설치 순서), 자리 `빈자리 N`(자리 번호). 연맹원이 정해지면 그 자리의 닉네임만 바꾸면 됩니다(번호는 줄·거리로 다시 매기므로 그대로).
- 계산·검사:
  ```
  node tools/make-sgd-layout.mjs                       # 곰덫1 자리 탐색 + 자리 100 + 깃발 → layouts/sgd.json (정밀 탐색, 몇 분)
  node tools/make-sgd-layout.mjs --trap 595,900 --total 100   # 곰덫1 자리 고정
  node tools/make-sgd-layout.mjs --check layouts/sgd.json      # 규칙 검사 (다른 연맹 영토는 margin 포함)
  ```
  규칙은 v2와 같습니다: 도시도 연맹 영토 안(곰 사냥 보상 조건), 자원지는 장애물, 오와 열 정렬, 깃발은 변 접촉으로 이어지게 계산(꼭짓점 접촉만 되는 게임에서도 통함). 깃발 번호는 번호대로 지으면 곰덫1 → 앞 번호 자리 순으로 영토가 되도록 정합니다.
- **자원 깃발 경로 (연구·깃발 비용 비율, 깃발 효율)** [layouts/sgd-resource.json](layouts/sgd-resource.json): 지금 영토(본부·배치 깃발·지금 깃발·세운 자원 깃발)에서 연맹 자원지를 영토에 넣는 깃발을 설치 순서대로 둡니다. 짓는 중 깃발이 1번부터이고, 세운 자원 깃발은 번호 없이 보여 줍니다. 자원지는 4칸 중 3칸 이상이 영토면 연맹 자원(app.js와 같음). 깃발은 스크린샷으로 확인한 땅(`sgd-area.json`의 `seen`) 안에만, 영토가 다른 연맹 영토(둘레 margin칸)와 겹치지 않게 둡니다. `/sgd`에서 "자원 깃발" 버튼으로 켜고 끄며, 목록에 붙는 영토·새로 얻는 자원·그 깃발까지 세웠을 때 예상 생산량이 나옵니다.
  ```
  node tools/plan-sgd-resources.mjs                   # → layouts/sgd-resource.json (비율 1:1:0.66:0.37, 변 접촉, 새 자원 깃발 최대 30, 개선 500회 — 3~5분, 석재·철은 비율만큼만 셈)
  node tools/plan-sgd-resources.mjs --ratio 1,1,0.66,0.37 --wmin 3 --max 30 --iters 500 --seed 7 --out /tmp/a.json
  node tools/plan-sgd-resources.mjs --ratio 1,1,0,0 --dry                          # 10-25 빵·나무 균형 계획
  node tools/plan-sgd-resources.mjs --goal weights --weights 100,4,3,1 --max 40   # 10-24 나무 우선 계획
  ```
  매번 지금 영토에서 깃발 1~depth개로 닿는 자리를 모두 훑어 (가치 증가 ÷ 깃발 수)가 가장 큰 경로를 확정하고, 개선 단계에서 가까운 깃발 1~4개를 빼고 다시 채우기를 반복해 같은 깃발 수로 가치가 더 큰 배치(같으면 깃발이 더 적은 배치)를 찾습니다. 번호는 남은 깃발 안에서 지금 영토부터 이어지는 경로 중 (가치 증가 ÷ 깃발 수)가 큰 순입니다. 가치는 3 × min(생산[종류] ÷ 목표 비율[종류]) + 새로 얻는 자원지 수(석재 0.66 · 철 0.37개로 셈 — 비율을 넘는 석재는 창고만 채우므로, `--cw flat`이면 모두 1개)입니다. 목표 비율 빵 1 : 나무 1 : 석재 0.66 : 철 0.37은 연맹 기술 전체 비용(빵 152.3M · 나무 152.3M · 석재 99.8M · 철 56.3M, [kingshotoptimizer](https://kingshotoptimizer.com/data/alliance-tech/))이고, 깃발 211개 이후 비용(1 : 1 : 0.67 : 0.36, [kingshotguide](https://www.kingshotguide.com/database/banner-requirements))도 거의 같습니다. 깃발 120개까지는 빵·나무만 듭니다(10-25 연맹 창고 사용 내역: 깃발 하나 빵 30K · 나무 30K). 생산량은 `rates`(창고 화면 K/h, `rates.nodes` = 그때 연맹 자원지 수)에 그 뒤 얻는 자원지 × 3.6K를 더한 값입니다. 자원지 1곳 = 3.6K/h는 10-24 → 10-25 사이 나무 6곳 +21.6K · 철 1곳 +3.6K · 석재 1곳 +3.6K로 확인했습니다. 깃발을 더 세우거나 스크린샷이 새로 오면 `resFlags`·`building`·`rates`를 고치고 다시 돌리세요.
- 게시본: `GET/PUT /api/sgd/layout`(KV `sgd`, 직전본 `sgd_previous`). 첫 게시 전에는 `layouts/sgd.json`을 보여 줍니다. 아직 `/sgd/admin` 편집기는 없어서, 바꾼 파일을 다시 배포하거나 로그인 토큰으로 `PUT /api/sgd/layout`에 올립니다.

### 캐슬 도시 배치 (/castle · /castle2)
킹스 캐슬 둘레에 누구 도시를 어느 칸에 붙일지 정하는 배치도입니다. `/castle`(Turret Layout), `/castle2`(Castle Layout), `/castle/map?p=1|2`(공유용 지도 한 장)는 같은 페이지([castle/index.html](castle/index.html) — 빌드가 `castle2/index.html`·`castle/map.html`로 복사, 로컬 `server.js`는 그대로 내줌)이고, [castle/castle.js](castle/castle.js)가 주소를 보고 배치 데이터를 고르거나(1·2) 공유 모드(`body.share`: 지도만 화면 가득, 편집 없음)로 엽니다. 공유 주소 `/castle/kor`([castle/kor.html](castle/kor.html))는 `/castle/map?p=1`·`?p=2` 두 장을 iframe으로 나란히 띄웁니다.
- 격자·캐슬 크기와 다른 연맹 도시 자리는 2026-11-07 캐슬 배치 플래너 스크린샷을 따랐습니다(캐슬 = 한 변 6칸, 한 칸 = 도시 하나). 칸 (i, j)에서 캐슬은 i, j = 0~5이고, i가 작을수록 북서쪽·클수록 남동쪽, j가 작을수록 북동쪽·클수록 남서쪽입니다. 열 = 캐슬에서 몇 번째 둘레인지(1~6). 위치는 "변(시계 방향 앞 꼭짓점에서 몇 번째)" 또는 "꼭짓점 바깥"으로 부릅니다. 게임 좌표는 아닙니다.
- 데이터 [layouts/castle.json](layouts/castle.json) = 게시본 `GET/PUT /api/castle/layout`(KV `castle`, 직전본 `castle_previous`, 첫 게시 전에는 이 파일), Castle Layout은 [layouts/castle2.json](layouts/castle2.json) = `GET/PUT /api/castle2/layout`(KV `castle2`, 직전본 `castle2_previous`). 계정·형식은 같습니다. 검사 함수는 `_worker.js`·`server.js`의 `validCastle`:
  ```
  { "memo": "메모(선택)", "members": [ { "n": "Khan", "i": 5, "j": 6 }, { "n": "Haaland" }, { "n": "Iro", "i": -1, "j": 2, "ext": true } ] }
  ```
  `i`·`j`가 없으면 미배치, `ext` = 다른 연맹. 같은 칸에 둘이면 뒤 사람이 미배치가 됩니다.
- 편집: **배치 편집** → **캐슬 편집 계정**(`castle/admin.txt`) 또는 기존 관리자 계정(`/v1/admin`과 같은)으로 로그인 → 지도 위 "미배치" 칸의 이름이나 지도의 도시를 끌어 빈칸에 놓기(다른 도시 위 = 자리 바꿈, 미배치였던 사람을 놓으면 그 칸 도시가 미배치로, 미배치 칸으로 끌어오면 빼기). 누른 뒤 빈칸을 눌러도 옮겨집니다. 놓을 때마다 서버 최신본을 받아 그 위에 같은 수정을 적용해 바로 `PUT`하므로 다른 관리자의 수정과 합쳐지고, 보는 화면은 30초마다 새 배치를 받아 옵니다.

### 관리자 계정
- 계정은 `admin.txt`(`아이디 / 비밀번호`)에 둡니다. `node tools/set-admin.mjs`를 실행하면 `.admin-secret`에
  `ADMIN_HASH` 값(무작위 salt + SHA-256 해시)이 만들어집니다. 비밀번호 자체는 어디에도 저장되지 않습니다.
- `/castle`은 따로 **캐슬 편집 계정**도 받습니다. `castle/admin.txt`(`아이디 /비밀번호`, 커밋 금지)로 `node tools/set-admin.mjs --castle`을 실행하면 `CASTLE_HASH` 값이 나오고, 이 값을 Cloudflare Pages 비밀값 `CASTLE_HASH`로 넣습니다(`npx wrangler pages secret put CASTLE_HASH --project-name kingshot-kor`, 넣은 뒤 다시 배포해야 반영). 로컬 `server.js`는 `castle/admin.txt`를 직접 읽습니다. 로그인할 때 `scope: 'castle'`을 보내면 캐슬 계정 → 관리자 계정 순으로 확인하고, 토큰은 맞은 계정의 해시로 서명하므로 캐슬 계정 토큰은 `/api/castle/layout`에만 통합니다.
- 비밀번호 확인은 **서버**(Cloudflare는 `_worker.js`, 로컬은 `server.js`)에서 합니다.
  로그인하면 12시간짜리 서명 토큰을 받고, 게시할 때 서버가 토큰을 검증합니다.
- `admin.txt`, `.admin-secret`, `api-token.txt`(어느 폴더에 있든, 예: `castle/admin.txt`), `screenshot/`은 배포 폴더(`dist`)에 들어가지 않고, 로컬 `server.js`도 내주지 않습니다.
- `/v1/admin`과 `/v2/admin`은 같은 계정을 씁니다.

### Cloudflare Pages 설정 (무료 계정 가능)
1. `npm run build` → `dist` 폴더가 만들어집니다(`_worker.js` 포함).
2. Workers & Pages ▸ Create ▸ Pages ▸ **Upload assets**에서 `dist` 폴더를 올려 프로젝트를 만듭니다.
3. Storage & Databases ▸ **KV** ▸ Create namespace (예: `kingshot-layout`).
4. Pages 프로젝트 ▸ Settings ▸ **Bindings** ▸ Add ▸ KV namespace: 변수 이름 `LAYOUT_KV`, 방금 만든 namespace 선택.
5. Settings ▸ **Variables and Secrets** ▸ Add: 유형 **Secret**, 이름 `ADMIN_HASH`, 값은 `.admin-secret` 파일 내용.
6. 바인딩은 새 배포부터 적용되므로 Deployments ▸ **Create deployment**로 `dist`를 한 번 더 올립니다.

이후 배치 변경은 `/v1/admin`·`/v2/admin`에서 게시만 하면 되고, 다시 올리는 것은 코드가 바뀌었을 때뿐입니다.
무료 한도: Functions 요청 하루 100,000회, KV 읽기 하루 100,000회·쓰기 1,000회. 정적 파일은 무제한입니다.
관리자 계정을 바꾸면 `set-admin.mjs`를 다시 실행하고 5번의 `ADMIN_HASH` 값을 새로 넣으세요.

`v1/index.html`·`v2/index.html`을 파일로 바로 열면 게시본을 불러올 수 없습니다. `node server.js`로 실행하세요.

## 기능

| 기능 | 데스크톱 | 모바일 |
|---|---|---|
| 배치 | 기물 버튼을 지도로 드래그, 또는 버튼 클릭 후 지도 클릭(연속 배치, Esc로 종료) | 버튼 탭 후 지도 탭 |
| 이동 | 좌클릭 드래그 | 한 손가락 드래그 |
| 다중 선택 | Shift + 클릭 | - |
| 삭제 | Del 또는 '삭제' | '삭제' |
| 지도 이동 | 우클릭 드래그 / 빈 곳 좌클릭 드래그 | 빈 곳 드래그 |
| 확대/축소 | 휠 (커서 기준) | 핀치 |
| 이름 변경 | 더블 클릭 | 길게 누르기 |

- 곰덫 거리/행군 시간 `(9 + 거리 × 2.7) / (1 + 버프율/100)`는 원본과 같은 식을 씁니다. 거리기준에서 곰덫을 고르면 Player 옆에 표시됩니다.
- Player 성은 항상 같은 색입니다. 곰덫·연맹자원은 영토(깃발 1/본부 1 = 1팀, 깃발 2/본부 2 = 2팀) 밖이면 빨간색이 됩니다.
- **빈 자리 (Free)**: 1팀 영토 안에서 성(2×2)이 규칙상 들어갈 수 있고 아무것도 없는 자리를 보라색 "Free"로 표시합니다. 개수는 지도 데이터 ▸ 레이어에 나옵니다.
- 데이터 저장/불러오기는 원본과 같은 JSON 배열 형식입니다.

### 지도 데이터 패널
- **레이어**: 산·호수, 연맹 자원지(빵/나무/석재/철), 구조물, 건설 금지구역, 자원 구역 링.
- **장애물 위 배치 막기**: 산/호수, 자원지, 구조물, 금지구역, 유적 안 연맹 건물, 비옥지 안 본부, 다른 기물과 겹치기를 막습니다. 막힌 위치에 이미 있는 기물은 노란 점선으로 표시됩니다.
- **영토 안 연맹 자원지**: 타일의 75% 이상이 영토에 들어간 자원지를 팀별·종류별로 셉니다.
- **주변 조회**: 좌표와 반경을 넣으면 구역, 장애물 타일 수, 가까운 자원지, 구조물 목록이 나옵니다. 항목을 누르면 그 위치로 이동합니다.
- **실시간 왕국 데이터**(kingshotstats 성 위치)는 꺼져 있습니다. 저장된 배치만 서비스합니다. 다시 켜려면 `app.js`의 `LIVE_ENABLED`를 `true`로 바꾸고 서버에 `/api/kingdom` 중계를 되살려야 합니다.
